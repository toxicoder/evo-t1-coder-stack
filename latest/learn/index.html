Learn the stack

The concepts behind the box — what the templates build, how a model request is routed, what the agents file seeds, and the rules a change follows.

What's on this page

  • Which page explains which part of the stack
  • The order that makes the pieces click, if you are reading them all
  • How this tab differs from the /ez-learn slash command in Grok Build

What this enables

  • Understanding a behaviour before trying to change it
  • Knowing which page owns a concept when two of them seem to

Not the same as the /ez-learn command. This tab is the concepts index for people reading the docs. /ez-learn typed at the Grok Build prompt turns the session you are in into durable memory - flush it into a session log, dream those logs into organized memory, remember one note, or browse and clear the store; it is this stack's copy of the upstream /flush, /dream, /remember and /memory. Skill authoring is its siblings: /ez-skillify captures the session that just worked and /ez-create-skill scaffolds one from a description. grok inspect lists the three once their seed has landed. A missing one is the skill-seed entry in troubleshooting.md.

How the pieces fit

Two templates turn a git URL into a running container: the plain workspace template, and devcontainer, which builds the clone's own .devcontainer on a DinD

DinD

Docker-in-Docker — a workspace's own sidecar daemon, addressed through DOCKER_HOST.

 sidecar. Both are pushed from this checkout, and both seed the agent config the workspace starts with.

Coder workspace templates owns the templates, the create form and the variables; Grok Build, Coder Agents, and the workspace terminal owns what runs inside the container once it is up.

The model lane

One OpenAI-compatible door, several backends behind it: the Arc 140T through IPEX-LLM

IPEX-LLM

Intel's XPU runtime that puts the models on the Arc 140T iGPU.

, and optional Spark boxes. Which one answers is a routing decision made in litellm-routing.md, not in the client — and that page also states the one thing the local model cannot do.

The assistant on the host

Hermes is the interactive assistant with the checkout, the compose project and the docker socket in reach, gated by approval prompts. Its public name is opt-in with STACK_PUBLIC_HOSTS=auto, which composes it from the naming parts; with that key empty the dashboard stays on the LAN. public-access.md is the page that decides what the box exposes.
