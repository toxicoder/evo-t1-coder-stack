**What this enables**

- Getting oriented in one screen before opening a terminal

This repository brings up one Compose project on a GMKtec EVO-T1 (Intel Core Ultra 9
285H, Arc 140T iGPU, 96 GB DDR5) and keeps it runnable by conversation, by dashboard, or
by `bazelisk`. Everything is a Bazel target addressed as
`bazelisk run //scripts:<stem> -- <args>`; `scripts/setup-host.sh` is the only script
meant to run straight from a shell.

The box deliberately runs **two isolated copies** of the stack: a stable one you work in
and a dev one you break. [Two stacks on one box](https://github.com/toxicoder/evo-t1-coder-stack#two-stacks-on-one-box)
in the README is the short version; [docs/config-updates.md](config-updates.md) covers
what a `git pull` leaves behind.

## What runs here

| Service | Host port | What it is for |
| --- | ---: | --- |
| Homepage (+ nginx sidecar) | 80 / 443 | The landing page, and the only thing publishing it |
| Coder | 3001 | Control plane: one container per workspace |
| Coder agent tunnel | 3002 | The plain listener a workspace agent dials via `host.docker.internal` |
| LiteLLM | 4000 | The single OpenAI-compatible door in front of every model |
| IPEX-LLM Ollama | — | The Arc 140T model runtime, never published to the host |
| Kasm | 3000 → 4443 | Streamed desktops; the wizard only on first boot |
| Hermes | 9119 | The host assistant, LAN / Tailscale only |
| SearXNG | 8181 | Keyless metasearch, the fallback search lane |

Ollama is reachable only from inside the compose network: LiteLLM is the gateway, and it
is the thing that carries the master key.
